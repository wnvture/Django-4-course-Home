# HOME · магазин и управление товарными данными

[![Tests](https://github.com/wnvture/Django-4-course-Home/actions/workflows/ci.yml/badge.svg)](https://github.com/wnvture/Django-4-course-Home/actions/workflows/ci.yml)

Учебный интернет-магазин мебели на Django с корзиной, заказами и рабочим кабинетом для загрузки товаров из CSV. Цены демонстрационные, в тенге. Реальные платежи и доставка не подключены.

Проект развивается из [учебного репозитория PythonHubStudio](https://github.com/PythonHubStudio/Django-4-course-Home). Исходная история сохранена. В этой версии обновлены Django, интерфейс, работа с корзиной и заказами; добавлены импорт с предпросмотром, отчёты по остаткам, миграции данных и регрессионные тесты. Это доработка учебной основы, а не заявление об авторстве исходного курса.

## Возможности

| Для покупателя | Для сотрудника (`is_staff`) |
| --- | --- |
| Каталог, категории, поиск по словам и артикулу | Остатки, количество единиц, стоимость по цене продажи |
| Фильтры наличия и скидок, сортировка по цене со скидкой | Фильтр низкого остатка с настраиваемым порогом |
| Гостевая корзина, объединение при входе | CSV-шаблон и загрузка до 1 000 товаров за раз |
| Регистрация, вход, профиль, история заказов | Предпросмотр изменений до применения |
| Проверка наличия и оформление учебного заказа | Атомарное применение, журнал импортов, экспорт CSV |

Заказ хранит название и цену на момент покупки: последующее изменение или удаление товара не меняет историю. Повторная отправка формы с тем же токеном возвращает тот же заказ. В PostgreSQL остатки защищены транзакциями и блокировками строк. SQLite подходит для локальной демонстрации; для параллельной работы используется PostgreSQL.

## Быстрый запуск

Нужны Python **3.11–3.13** и Git. Для первого запуска достаточно SQLite, отдельный сервер базы не нужен.

```bash
git clone https://github.com/wnvture/Django-4-course-Home.git
cd Django-4-course-Home
python -m venv .venv
```

Windows PowerShell:

```powershell
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe manage.py migrate
.venv\Scripts\python.exe manage.py seed_demo
.venv\Scripts\python.exe manage.py createsuperuser
.venv\Scripts\python.exe manage.py runserver
```

macOS / Linux:

```bash
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python manage.py migrate
.venv/bin/python manage.py seed_demo
.venv/bin/python manage.py createsuperuser
.venv/bin/python manage.py runserver
```

Открыть **http://127.0.0.1:8000/**. `seed_demo` загружает 12 товаров и копирует изображения в `media/`. Команда работает только с пустым каталогом, повторный запуск ничего не перезаписывает. Цены в ней вымышленные; это не пересчёт цен из старых фикстур.

Повторный запуск: `.venv\Scripts\python.exe manage.py runserver` на Windows или `.venv/bin/python manage.py runserver` на macOS/Linux. Также доступны `scripts/start.ps1` и `scripts/start.sh`: они устанавливают зависимости, применяют миграции и запускают сервер; демонстрационные данные и администратор создаются отдельно.

## Проверить за 5 минут

1. Открыть каталог, найти «диван» или артикул `HOME-00009`, добавить товар в корзину.
2. Зарегистрироваться: гостевая корзина сохранится. Оформить заказ с телефоном `+7 700 123 45 67`.
3. В личном кабинете проверить заказ. При заказе остаток уменьшается.
4. Выйти и войти под администратором, созданным командой `createsuperuser`.
5. Открыть `/inventory/`, загрузить `examples/products.csv`, проверить предпросмотр и нажать «Применить импорт».
6. Проверить остатки и скачать CSV-отчёт. `/admin/` позволяет редактировать товары и менять статус заказа.

## Импорт CSV

Кодировка **UTF-8**, разделитель `;`, `,` или табуляция, максимум **2 МБ / 1 000 товаров**. Пример — [examples/products.csv](examples/products.csv). Файл из интерфейса содержит правильные заголовки и пример строки, которую нужно заменить.

Обязательные поля: `sku`, `name`, `category`, `price`, `quantity`. Необязательные: `discount`, `description`. Поддерживаются русские заголовки: «Артикул», «Название»/«Наименование», «Категория», «Цена», «Остаток»/«Количество», «Скидка», «Описание».

- Артикул — постоянный ключ товара. Совпавший артикул обновляется; новый создаётся. Удаления через импорт нет.
- Остаток в файле **заменяет текущее количество**, а не прибавляется к нему.
- Цена неотрицательная, до двух знаков после запятой; скидка от 0 до 100; количество — целое неотрицательное число.
- Повторяющиеся артикулы и названия, конфликты с другим товаром и неверные значения отклоняются до записи.
- При ошибке применения отменяется весь пакет. Изображения существующих товаров сохраняются.
- Предпросмотр действует 24 часа и доступен для применения только загрузившему сотруднику. Если товар изменился после предпросмотра, нужен новый файл/предпросмотр: продажа не будет молча затёрта.
- Повторное применение выполненного пакета ничего не меняет. Нормализованные строки и SHA-256 файла сохраняются в журнале.

Экспорт остатков — отдельный отчёт, а не шаблон обратного импорта. Потенциальные формулы в текстовых ячейках экранируются для просмотра в Excel.

## Проверки

```bash
python manage.py collectstatic --noinput
python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py test --verbosity 2
```

Запускайте команды через Python из `.venv`, как в инструкции выше. GitHub Actions проверяет SQLite на Python 3.11/3.12/3.13 и PostgreSQL 17 на Python 3.12. Отдельный тест в PostgreSQL проверяет двух покупателей, претендующих на последнюю единицу товара; в SQLite он намеренно пропускается. Есть тест обновления заполненной старой базы с дублирующимися корзинами.

Подробнее об устройстве и ограничениях: [docs/architecture.md](docs/architecture.md). Обновление существующей установки: [docs/upgrade.md](docs/upgrade.md).

## Конфигурация и границы

Настройки можно задать через переменные окружения или локальный `.env` по образцу [.env.example](.env.example). По умолчанию включён локальный режим отладки. Ключ разработки создаётся автоматически в игнорируемом `.local_secret_key`. Пароли и реальные пользовательские данные в репозиторий не входят.

Для PostgreSQL задайте `DATABASE_URL=postgresql://USER:PASSWORD@HOST:5432/DATABASE` перед миграцией. Пользователь тестовой базы должен иметь право `CREATEDB`, если вы запускаете тесты. Для реального размещения потребуются собственный секретный ключ, `DJANGO_DEBUG=False`, разрешённые хосты, HTTPS, WSGI/ASGI-сервер, настройка отдачи загруженных изображений и резервного копирования. Запустите `python manage.py check --deploy`. Схема доверия к reverse proxy настраивается владельцем сервера под конкретную инфраструктуру.

В проекте пока нет платёжного шлюза, писем восстановления пароля, расчёта доставки, отмены заказа с возвратом остатка и интеграции с 1С. Корзина не резервирует товар: окончательная проверка происходит при оформлении. Для публичной эксплуатации также нужны ограничение частоты входа, мониторинг и политика хранения данных. Учебный сервер `runserver` не предназначен для публичной эксплуатации.
